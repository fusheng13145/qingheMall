Qinghe Mall · Design System v1.0

三端 UI 设计规范
让管理员、商家、顾客各归其位

针对当前三端共用同一套绿色主题、Admin/Merchant 布局近乎克隆导致的"混杂不清"问题，本规范提出「统一内核 + 三套皮肤」的设计架构：保留青禾品牌内核，按角色赋予差异化视觉语言、交互密度与组件形态，并给出可直接接入工程的 token 与迁移路线。

用户端 · 翠绿 / 亲和 商家端 · 琥珀 / 经营 管理端 · 墨石 / 严谨 Vue 3 · Vite · CSS 变量驱动
01 / Diagnosis

现状诊断：为什么三端"混杂不清"

通过审阅 frontend/src/App.vue、AdminLayout.vue、MerchantLayout.vue、AppHeader.vue，问题根因高度集中，并非"样式简陋"而是架构层面缺失角色皮肤。

① 单一主题变量

App.vue 中 --color-primary 全局锁定为 #10b981。三端无各自的语义令牌，品牌绿被同时用于用户、商家、管理员三套界面，第一眼无法区分角色。

② 布局近乎克隆

AdminLayout 与 MerchantLayout 几乎逐行相同：同样的 240px 侧边栏、同样的绿色 sidebar-logo 渐变、同样的 nav-item 样式、同样的"返回商城"按钮。管理员与商家进入后台，看到的几乎是同一个界面。

③ 共用组件库

AppHeader / AppFooter / ProductCard 三端共用，且均引用全局绿。商家端需要的"经营数据看板"、管理端需要的"高密度表格"在现有组件里没有专门形态，只能套用同一套卡片与列表。

结论三端仅靠"文字标签 + 个别图标"区分，视觉语言高度同质，角色认知弱、误操作风险高。
核心矛盾：品牌绿是"青禾"的资产，但它被不加区分地铺在三套界面上，反而消解了品牌识别，也让三端用户（顾客 / 店主 / 平台运营）失去了属于自己的操作语境。
02 / Strategy

设计策略：统一内核 + 三套皮肤

不推翻现有工程，而是把"一套全局变量"升级为"一套基础令牌（内核）+ 三层皮肤令牌（角色）"。基础令牌保证三端是"同一个产品家族"；皮肤令牌让三端"各司其职、一眼可辨"。

品牌家族延展原则

  • 品牌色留给顾客（前台）。青禾翠绿是面向消费者的公共资产，保留在用户端，强化"我在逛青禾商城"的认知。
  • 内部作业系统功能化配色。商家端与管理端是内部 B 端作业台，采用功能化锚点色（琥珀＝营收经营 / 钢蓝＝系统管控），用色强化角色而非承载品牌。
  • 内核一致、皮肤分化。间距、圆角标度、阴影标度、动效、字体家族、中性灰全部共享；分化只发生在"锚点色 / 信息密度 / 圆角倾向 / chrome 明暗 / 数据字体"五个旋钮。

三端角色定位

C 端 · 顾客
青禾商城前台
亲和、流畅、浏览优先。圆润留白、轻盈动效，让人想逛、好买。关键词：温暖 / 直观 / 愉悦。
B 端 · 商家
商家工作台
经营效率与数据看板并重。介于顾客与管理之间，强调"我的店、我的钱、我的货"。关键词：务实 / 清晰 / 有数。
平台 · 管理员
平台管控台
专业、严谨、数据密度高。深色 chrome、紧凑表格、等宽数字，为"看全局、管全局"而生。关键词：冷静 / 致密 / 高效。
差异化优先级：先用锚点色和chrome 明暗建立"一眼可辨"的第一印象，再用信息密度和组件形态巩固"各归其位"的操作语境。管理端以"深色侧边栏"作为最强识别特征。

04 / Differentiation

三端差异化设计语言

每个端都有独立的设计原则、风格方向、识别特征与色板。下方色板为该皮肤的语义令牌取值。

4.1 用户端（C 端 · 青禾商城前台）

设计原则：简洁直观、亲和友好；以"浏览与下单流畅"为第一目标，弱化后台感。

风格方向：明亮通透的白底 + 品牌翠绿点缀；大圆角、轻阴影、充足留白；微动效（卡片悬浮上浮、加入购物车弹性反馈）增强愉悦感。

识别特征：绿色渐变 Logo、圆润胶囊按钮、价格用品牌红强调、商品卡大图圆角。

Do：大图、强 CTA、清晰价格与促销标签。
Don't：出现密集表格、专业术语、深色面板。

4.2 商家端（B 端 · 商家工作台）

设计原则：兼顾经营效率与数据看板；介于用户端亲和与管理端冷峻之间，体现 B 端业务属性。

风格方向：白底 + 琥珀金锚点；中等圆角（12px）、克制阴影；首页以"经营数据卡 + 待办"为主，列表与表单清晰高效；KPI 数字用等宽字体突出"有数感"。

识别特征：琥珀金主操作、店铺概览数据卡、营收/订单/商品三栏指标、明确的"本店"归属提示。

Do：突出营收与待办、用金色标记关键动作。
Don't：过度花哨或过度严肃，避免与管理端混淆成"另一个后台"。

4.3 管理端（平台 · 管控台）

设计原则：专业、严谨、数据密度高、操作效率优先；为平台运营"看全局、管全局"服务。

风格方向：深色侧边栏（墨石）+ 浅色内容区构成最强识别；紧凑间距、小圆角（8px）、细描边、高密度表格；ID/金额/状态用等宽字体与状态色；强调信息层级而非装饰。

识别特征：墨石深色导航栏、钢蓝强调色、紧凑表格、状态徽标、批量操作工具条。

Do：高密度列表、批处理、筛选器、明确的状态机。
Don't：大图营销、圆润可爱、与商家端共用视觉。

07 / Implementation

落地实施建议

7.1 CSS 架构：data-skin 驱动

在现有 App.vue 的 data-theme（亮/暗）之上，新增 data-skin 维度，二者正交。语义令牌由各皮肤覆盖，组件只引用语义令牌。

层级载体职责
基础层styles/qinghe-skins.css §0中性灰、间距、圆角/阴影标度、动效、字体家族（三端共享）
皮肤层styles/qinghe-skins.css §1–3按 [data-skin] 覆盖 --brand / --chrome / --radius-card / --density / --font-data 等语义令牌
主题层现有 [data-theme]亮/暗背景与文字反转（保留现状）

挂载点：用户端在 .app 设 data-skin="user"；商家端在 MerchantLayout 根设 data-skin="merchant"；管理端在 AdminLayout 根设 data-skin="admin"。本规范附带的 qinghe-skins.css 可直接放入 frontend/src/styles/ 引用。

7.4 风险与回滚

风险：皮肤变量若直接覆盖全局 --color-primary，可能影响仍依赖全局变量的旧页面。 规避：皮肤选择器限定在布局根（[data-skin="x"] .xxx 或根元素作用域），不污染全局；分阶段提交，每步可独立回滚。
回滚：删除 data-skin 挂载即退回现状（单一绿色主题），CSS 文件独立、互不耦合。

7.5 验收标准（可量化）

  • 一眼可辨：用户端、商家端、管理端截图并排时，主色与 chrome 明暗三者互不相同（绿 / 琥珀 / 墨石+钢蓝）。
  • 密度梯度：管理端表格行高 ≤ 用户端表格行高 × 0.7；商家端居中。
  • 组件复用率：通用按钮/表格/表单在三个端复用，专属覆盖不超过组件总量的 30%。
  • 无回归：前端 npm run lint 与 npm run test 保持全绿；亮/暗主题在三个端均可用。
  • 令牌完整：三端均存在完整的语义令牌定义，新增页面只需挂 data-skin 即可获得正确皮肤。
