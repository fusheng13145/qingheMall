# PROJECT-SPEC.md — 项目定位、产品目标与功能范围

> 派生视图（权威源：[青禾商城手册.md](../青禾商城手册.md) v8.0 §1/§4/§9）。本文回答「做什么、为谁做、做到什么程度」。

## 1. 项目定位

**青禾商城（qingheMall）**：全品类一站式综合购物平台实战项目。平台型三方结构——**平台运营**（治理与抽佣）、**入驻商家**（自主经营）、**顾客**（消费与售后），覆盖数码家电、服饰美妆、食品生鲜、家居百货等品类。

项目性质为**生产级学习工程**：以真实电商业务为载体，完整实践从需求、架构、实现到测试、可观测、部署与文档的全工程链路。

## 2. 产品目标

| 目标 | 度量 |
| --- | --- |
| 完整业务闭环 | 浏览 → 加购 → 下单 → 支付 → 发货/物流 → 收货 → 评价/退款 全链路可跑通 |
| 平台化能力 | 商家入驻审核、自主建品与营销（券/秒杀）、按订单结算分账（佣金 5%）、平台治理后台 |
| 高并发正确性 | 秒杀三重防超卖（Redis 闸门 + CAS + 唯一约束）；分账金额分币守恒 |
| 工程质量 | 双语言测试全绿 + 契约快照防漂移 + 双视口 e2e + 全链路 API 冒烟 |
| 可运维 | 容器化一键部署、监控告警、结构化日志、备份恢复预案 |

## 3. 功能范围（已实现）

### 3.1 顾客侧
- 商品浏览/检索（ES 全文 + 中文分词，MySQL 降级）/ 品牌 / 排序；商品详情与规格；**店铺主页**（商品 + 店铺券/秒杀 + 评分销量聚合）。
- 购物车（勾选/数量/结算）；收货地址簿。
- 下单（单件 + 购物车批量）、**优惠券**（平台券/店铺券、满减/折扣、**购物车级核销**：门槛按合计、优惠按比例分摊）、**秒杀**（Redis 闸门限流 + 归属校验）。
- 支付（微信/支付宝通道解析，未配凭证回退 MOCK）；订单管理；物流跟踪（CAS 逐级推进）；退货退款（申请 → 商家审核 → 库存回补/券释放/分账冲销）。
- 评价（评分 + 文本）与商家回复展示；个人中心（资料/地址/我的券/我要开店）。

### 3.2 商家侧
- 入驻申请与审核状态机；商品与 SKU 管理（上下架）；订单发货（承运商 + 运单号必填）；物流推进。
- 营销自建：优惠券/秒杀活动（本店归属强校验）；评价管理与回复；结算中心（概览/流水/结算单）。

### 3.3 平台侧（管理后台）
- 仪表盘与营收报表；用户与角色管理；商家审核；商品/订单治理（含发货与状态机改单）。
- 平台券/秒杀管理；结算审核放款；**首页运营位管理**；退款工单处理。

### 3.4 平台工程能力
- Elasticsearch 检索（写双写、读降级）；库存 Cache-Aside（命中率指标）；per-user 限流；延迟关单队列。
- 监控告警（Prometheus/Alertmanager/Grafana + Loki 日志）；Vault 密钥托管（dev 环境变量兜底）；CI/CD（GitHub Actions → GHCR）。
- 备份恢复预案（快照 + 轮转 + 演练模式）。

## 4. 明确不在范围内（当前时点）

- 真实支付网关原路退回（商户凭证未就绪，回退 MOCK；见待完成项 A1）。
- 多实例水平扩展演练（MQ 削峰、读写分离为备选项）。
- 营销自动化（Push/优惠券定向投放）、直播/内容电商等业务扩展。
